# ADR-0006 — React Native correlation demo

- Date: 2026-10-14
- Status: **Accepted for implementation** (owner asked to start the React Native demo; open to review before merge)

## Context

PLAN.md's fourth follow-up: a small React Native client that reads `X-Request-Id` and `Server-Timing` to separate perceived latency from backend time, with `trustIncoming` enabled explicitly, and only counted as mobile evidence if it runs on a real client. The owner's research notes stress that a web or Node demo is not mobile evidence and that client-minus-server is not network time.

## Decisions

1. **Shared, platform-neutral correlation module.** `examples/react-native-correlation/correlation.js` uses only `fetch`, `AbortController`, an injected clock and an injected ID generator. The Expo app and the Node tests import the same file (Metro `watchFolders`), so the logic that is tested is the logic that ships.
2. **One request ID per physical attempt**, generated by the client (`expo-crypto` in the app, `node:crypto` in Node). Operations group attempts. The client validates its own IDs against the server's accepted format before sending.
3. **The example server trusts client IDs** (`trustIncoming: true`), so a request the client abandoned can still be found in the server log. The join falls back to the server's response header ID when trust is off, and says "unknown" when neither is available. Both modes are tested.
4. **Names, not guesses.** `clientAttemptMs`, `responseMs`, `operationMs` (app, labelled as a proxy until the first frame after commit) and "not measured by server" (`clientAttemptMs − durationMs`). The difference is never called network time. Below 20 ms the join declines to interpret the split.
5. **Expo app outside the npm workspace.** `app/` has its own `package.json` and lockfile so that the repository's root install stays small. Expo SDK 57 with React Native 0.86.3 and React 19.2.3, the versions `expo install --check` accepts.
6. **Example server binds to loopback** by default; `HOST=0.0.0.0` is opt-in for a phone on a trusted LAN and prints a warning.

## Verification and its limits

- Correlation and join: Jest tests over real HTTP against the example API.
- App: `expo install --check` and `expo export --platform android` (Hermes bytecode), and a check that the shared module is inside the bundle.
- Android emulator (owner approved installing one): Android 15 x86_64 image, Expo Go 57.0.9. All five scenarios ran; all six attempts joined. See examples/react-native-correlation/results/2026-10-14-android-emulator.md.
- Not verified: a physical phone on a real network, and iOS.
- The emulator run found that `SafeAreaView` from `react-native` is deprecated in 0.86 and did not clear the Android status bar; the app now uses react-native-safe-area-context.

## Consequences

- Root `npm test` now runs every workspace that has a test script (express-observe and this example).
- Client attempt logs reach the join tool by copying the Metro console; there is no upload endpoint, so the example server never accepts client data.
